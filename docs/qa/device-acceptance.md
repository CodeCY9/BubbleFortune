# V0.1 / V0.2 设备验收步骤

本表是待执行步骤，不是通过报告。每台设备单独记录，结果汇总到 [ROADMAP](../ROADMAP.md)。

## 环境与启动

记录日期、设备型号/CPU/GPU、系统、浏览器版本、视口、DPR、网络、画质偏好与实际档位、是否开启减动态和快速动画。性能使用生产前端：先 `npm run db:up`，两个终端分别运行 `npm run dev:server` 与 `npm run build` 后的 `npm run preview`。同一 3000 端口不要同时运行 dev 和 preview。

桌面从 http://localhost:3000 打开；手机和平板连接同一局域网，使用启动日志中的本机局域网地址。PWA 安装/更新需要 HTTPS 安全上下文（本机 localhost 除外）；普通局域网 HTTP 的安装失败不能归因于应用图标或 manifest。

## 采样与功能

1. 设置 → 开发诊断与本地性能采样 → 开始采样，关闭设置再操作；采样仅在页面前台且 3D 就绪时计入。
2. 分别记录开幕、静态舞台、连续开箱、报价和结算。每段停止后立即导出 JSON；阶段/画质/尺寸改变会开始新段，避免覆盖未保存的样本。导出结果同时保留平台、浏览器语言、横竖屏、网络类型、RTT、下行估计和省流量状态，便于复现实验条件。
3. 标准/节能各测试一次，报告样本数、FPS、p50/p95/min/max/平均帧时间、加载时间、绘制调用/三角形/纹理。冷启动加载与故障重试加载分开记录，不能用故障恢复耗时代表正常加载。
4. 桌面目标 60 FPS，中端手机 30–45 FPS，节能档稳定 30 FPS。确认慢帧来自 CPU/GPU/资源中的哪一处后再优化，每次保留相同场景与条件的前后样本。
5. 360 px 起检查金额、大字、弹窗、底部安全区；平板横竖屏分别确认金额面板和操作区。旋转/改画质/调整窗口不得创建新局；记录个人箱、已开金额、轮次前后是否一致。
6. 键盘覆盖开局、选择箱、接受/拒绝、最终选择、设置、战绩和公平弹窗；Escape 返回触发按钮。真机触控不依赖 hover，开箱动画期间不能连续触发其他箱子。
7. 开箱动画完成后才划掉金额和更新记录；报价/最终选择也等待揭晓。打开设置或成交确认不会暂停服务器计时，报价过期时确认应撤销。

## 故障与 PWA

- 开箱与报价期间分别断网/恢复：提示清楚，服务器结果不由客户端改写；超过 120 秒重连保留期时提供新局操作。
- 在独立验收对局中重启游戏服务：进行中会话明确失效，已结算游客历史仍可查询；不要把进行中恢复写成已支持。
- 阻断当前 GLB，检查 HTML 箱子操作与错误提示；解除阻断后重试恢复 3D，个人箱与已揭晓状态不丢失。恢复所有网络和资源模拟设置。
- 已安装 PWA 在联网时完成一局；离线重新打开只允许静态壳和明确提示，不创建本地随机对局。API、认证、重连令牌及私人历史响应不得进入缓存。
- 产生新构建：进行中禁止激活更新，结束后明确点击更新才重新载入；更新前后游客历史保留。
- 主动创建公开摘要、复制及系统分享；无分享动作不公开私人历史。打开分享页只见虚拟得分、AI、原始/最终箱和结算方式。
