# challenge-26-v2 挑战模式

状态：业务代码已交付，设备、网络、性能和秘密隔离仍待验证。

挑战模式独立使用 `challenge_26` Colyseus 房间，沿用 26 箱轮次、服务端随机映射、权威命令、幂等和公平证明基础能力，不改变 `classic_26`、`duel_26` 或 `auction_26`。

- 前三轮报价不可接受，必须拒绝后继续开箱。
- 开满 24 箱后自动保留个人箱，禁止最终交换。
- 未开箱金额不进入公共快照；挑战客户端隐藏金额栏。
- 每局提供一次“询价”动作。询价只记录为一次性挑战能力，不公开理论期望或内部报价参数。
- 使用服务端版本化的 `volatile-v1` 随机金额池；池内容不进入开局公共快照，只在终局公平证明中公开。
- 首次开箱前可购买一次保险契约；当前配置为费用 500、保底 5,000，结算收益为 `max(原收益, 5,000) - 500`。
- 每次开箱倒计时为 15 秒，超时仍由服务端随机选择合法箱子。
- 报价阶段提供一次“拒绝加码并继续”能力；该动作等价于拒绝当前报价并消耗能力，不改变报价内部参数。
- 26 箱仍采用 `6 / 5 / 4 / 3 / 2 / 1 / 1 / 1 / 1` 轮次。
- 终局写入游客历史时使用 `challenge-26-v2` 规则版本，并包含保险结算字段。

当前限制：挑战模式复用经典 AI 报价策略；业务代码仍需设备、网络、秘密隔离和历史写入验收。
