# tournament-v1 锦标赛

状态：业务代码已交付，待验证。`tournament_26` 提供 8/16/32 人大厅、服务器生成晋级树、可选嵌入式 `duel_26` 或快速 `survivor_26` 子对局和终局排名；尚未通过设备、网络、重连、数据库和安全验收。

- 支持 8、16 或 32 人淘汰赛；创建房间时固定选择资本家对决或快速生存战格式，服务器为每一轮生成独立子对局。快速生存战使用两名玩家的 `survivor_26` 状态机，自动开始个人箱选择，不重复开放子对局大厅。
- 服务端生成晋级树和对局映射，客户端只能提交当前子对局的合法意图，不能提交或改写胜负。
- `MATCH_COMMAND` 只允许携带一种子命令：`duelCommand` 或 `survivorCommand`。快速生存战子对局由服务器直接分配两席并自动开始，仍沿用子对局的状态版本、命令序号、幂等键、断线保留和终局证明。
- 支持房间观战、终局证明、参与者可读取的回放摘要接口和参与者授权的公开排名分享摘要；当前子对局和观战投影复用 26 箱 3D 舞台，观战只消费公共箱状态。
- 创建者可通过 4–64 个字符密码将房间设为私密；服务端只保存密码哈希，密码不进入公共快照或回放摘要。密码房默认 `isPrivate=true`、`ranked=false`，历史照常保存但不更新赛季锦标赛统计；创建时可由服务端显式锁定 `ranked`。
- 创建者可关闭观战、关闭快捷表情，并从 `classic` / `starry-neon` 白名单选择视觉主题；格式、人数、观战、快捷表情、主题和私密房配置在创建时锁定，开始后不允许修改。快捷表情设置会传递给快速生存战子对局，资本家对决子对局不新增聊天能力。主题只影响舞台与界面表现。
- 平局规则已固定为 `sha256-match-seat-v1`：当嵌入式对决或快速生存战出现双方最高分相同，服务端使用 `SHA-256(tournamentId + matchId + ruleId)` 的首字节从参赛席位中确定晋级者。该裁决只执行一次，不递归重赛；裁决标记写入晋级树、终局结果和审计事件，客户端不能提交或影响该值。
- 本版本不发放真实货币、可兑换物品或场外奖励；赛季排名与 Elo/模式统计是唯一正式反馈，私密房和未计排名房仍不更新正式赛季统计。未来若引入活动奖励，必须增加独立版本化规则，不能复用本规则静默发放。
- 弃权、延迟、平局和上述裁决继续沿用现有终局证明、回放和分享边界。

本轮不实现赛季外奖励和递归重赛策略；确定性平局裁决已接入。锦标赛终局已通过 outbox/PostgreSQL 保存并提供参与者历史查询。房间入口已开放，但必须先完成本规格列出的验收后才能标记完成。
