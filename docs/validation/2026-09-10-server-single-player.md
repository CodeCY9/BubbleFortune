# 26 箱服务端权威单人迁移验收

日期：2026-09-10。范围：恢复被额度中断的单人迁移，保留箱 v009、舞台 v007 与已确认的动画揭晓规则。本记录证明功能迁移，不替代资产真机性能或 V0.1 全量发布验收。

## 交付

- [公开配置](../../packages/protocol/src/config.ts) 与 [协议](../../packages/protocol/src/types.ts)：仅 26 箱，轮次 6 / 5 / 4 / 3 / 2 / 1 / 1 / 1 / 1，共开 24 箱后最终保留/交换。
- [GameEngine](../../apps/game-server/src/engine/GameEngine.ts)、[Classic26Room](../../apps/game-server/src/room/Classic26Room.ts)：秘密随机映射、报价、超时和唯一结算由服务器负责；校验身份、阶段、版本、命令序号、幂等键、报价标识与截止时间。
- [客户端接入](../../src/hooks/useGameState.ts)、[同步规则](../../src/utils/clientSync.ts)、[表现层](../../src/utils/presentationManager.ts)：收到权威确认后播放动画；同一时刻只开一个箱子，结束后更新金额栏、已开记录、报价与终局选择。刷新恢复已确认局面，不重播历史开箱。
- [Box3D](../../src/components/Box3D.tsx)：动画完成回调绑定对局与表现周期；旧回调不会误解锁新局，缺动画片段和动画未回调有恢复路径。
- [启动器](../../scripts/dev.mjs)、[Vite 代理](../../vite.config.ts)、[README](../../README.md)：`npm run dev` 同时启动前后端；浏览器经 `/game` 同源代理通信。Windows 启动使用 Node 直接运行入口。
- [手机布局](../../src/components/Header.tsx)：显示倒计时与连接状态；窄屏镜头覆盖所有箱位，提供箱号选择控件；报价时金额列表默认折叠，可用键盘展开，和操作按钮分开布局。

## 实际浏览器检查

环境：Windows，Codex 内置 Chromium 浏览器，开发服务器前端 3000 / 服务端 2567。手机尺寸是视口模拟，不是真实手机；手机自动低画质、桌面标准画质，均为 26 箱。

| 尺寸 / 场景 | 观察与结果 |
|---|---|
| 1280×720，普通速度开箱 | 选择 1 号个人箱，打开 2 号期间其他箱子全部禁用；动画中本轮剩余次数和已开记录保持原值；动画结束后显示 1,000 并允许下一次操作 |
| 1280×720，开箱后刷新 | 保留同一局与 1,000 揭晓记录，没有历史开箱动画重播，可以继续游戏 |
| 390×844，手机选择与完整一局 | 通过箱号控件依次打开 2–25 号，经过全部轮次；第 24 次开箱动画完成后进入最终选择，没有多生成一次报价 |
| 360×800，最终交换及刷新 | 用 Enter 激活交换到 26 号，结算 25,000；刷新后仍为 25,000，原始个人箱 1 与最终个人箱 26 一致 |
| 360×800，手机报价 | 头部按钮、轮次、倒计时可见；Enter 展开“查看剩余金额”，金额列表可滚动，接受/继续按钮仍可见且可操作；选箱控件不穿过报价卡片 |
| 手机买断，随后 1280×720 查看结算 | 报价 64,900，接受后结算恰为 64,900，个人箱揭晓为 300；无 NaN |
| 临时恢复请求失败后重试 | 对测试标签页临时阻断 `/game/*` 并刷新，出现明确恢复失败提示；解除阻断后点击“重新连接”，恢复原局 64,900 结算，证明一次失败未清掉有效令牌；未隐式创建新局 |

网络模拟最初未切断已有 WebSocket，因此不把该尝试计为断线通过；有效证据是随后明确阻断恢复请求、再解除并重试。已撤销所有请求阻断、离线模拟和视口覆盖。未记录或公开重连令牌与隐藏映射。

## 限制与下一步

- 当前仅单人内存会话，断线席位保留 120 秒且计时继续；服务重启不能恢复旧局。未实现账号、数据库战绩、多人或可验证公平。
- 手机真实触控、移动网络切换/丢包、低端 GPU、帧率与资源加载失败尚未完成实机验收；不把视口模拟当作性能证明。保留/交换两条规则路径由服务端测试覆盖，浏览器本轮完整终局实测为交换。
